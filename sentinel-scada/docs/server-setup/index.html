Server Setup Guide

Putting SentinelSCADA on a Windows server, step by step, from a clean machine to a working installation.

Draft This guide is being written. Parts marked as an outline will be filled in as each step is proven on a clean machine.

SentinelSCADA is designed to run on a private network, with no connection to the Internet needed or recommended while it is running. If you want to reach it from outside, that is your choice to make, for example through your own VPN. This guide does not cover it. An Internet connection is only needed briefly during setup, to download the Microsoft runtimes in Part 2.

SentinelSCADA can be installed on a suitable Windows 11 computer, on Windows Server, or on a virtual machine running either. We tested every step on a clean Windows Server 2022 virtual machine in VirtualBox, and Part 1 shows how to build one, in case that is helpful. If you already have a machine to install on, skip Part 1.

Parts

  1. Part 1: A VirtualBox Virtual Machine
    Optional. Building a clean Windows Server machine in VirtualBox: memory, disk, installing Windows, Guest Additions, a network your own PC can reach, and a first snapshot.
  2. Part 2: Install SentinelSCADA
    What the server needs, getting the installer across, running it, and preparing the machine with the Prepare script.
  3. Part 3: First Start and Security
    Starting the Launcher, the bind address, Design Mode, XML mode, changing the default passwords, roles, and switching to Run.
  4. Part 4: Remote Clients and Starting Automatically
    Connecting from another computer, the one-client limit, Allow Remote Admin, shutting down safely, and starting at logon.
  5. Part 5: Trying It with a Simulator
    Optional. Running a Modbus simulator on the same machine and watching a live value, read and write.
  6. Part 6: Moving to SQLite Mode
    What SQLite mode adds, the one-way step, what happens to existing users, and checking the default passwords.
  7. Part 7: HTTPS and Certificates
    Encrypting the connection between the server and its browsers: making a certificate, switching HTTPS on, trusting it on each client, and what to expect afterwards.
